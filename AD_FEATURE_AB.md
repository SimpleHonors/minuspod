# Ad-Feature A/B: Ours (2.5.6, `simplehonors-patches`) vs Upstream (2.8.10, `upstream/main`)

**Bottom line:** Our fork's signature ad feature is the **Ad Inbox triage workflow** — a whole page + backend service that upstream simply does not have. Upstream, meanwhile, shipped three net-new ad features on top of the shared waveform editor that we never built: a Sponsors management page, a per-feed "learned ad positions" experiment, and an ad-distribution panel. The shared `AdReviewModal` waveform editor exists on both sides but we forked it hard (+258 lines: peer overlays, jump-to-peer, zoom, play-while-drag). Our Python detection backend is a heavy rewrite/simplification (~1,080 net lines deleted), so any backend merge in the ad area is the real danger zone.

> Note: the task referenced `CHANGES_VS_UPSTREAM.md`; **that file does not exist in the repo**, so every claim below is grounded directly in `git`/source, not the doc.

1. **The entire Ad Inbox** — `AdInboxPage.tsx`, `api/adInbox.ts`, `src/ad_inbox_service.py`, `src/api/ad_inbox.py`. No upstream equivalent exists.
2. **Bulk confirm/reject/skip** with bounded-concurrency + progress.
3. **Save-and-Next + session skip set** triage flow.
4. **Peer-overlap triage hints + contained-ad hiding** (`computeOverlapPeers`, `isContainedByEndorsedPeer`).
5. **AdReviewModal peer-overlay markers + jump-to-peer + hover popover** (+258 lines over upstream's modal).
6. **Play-while-dragging-pin** scrub with playhead restore + persisted pref.
7. **Our simplified detection backend** (~1,080 fewer lines) — preserve unless we deliberately re-adopt upstream's algorithm.

## Conflict hotspots (hardest to merge in the ad area)
- **`src/ad_detector/__init__.py`** — biggest landmine. We deleted ~619 lines from this region; upstream's #362 (positional prior) and #320 (multi-word sponsors) both edit it. A 3-way merge here will be a near-total manual rewrite. Adopting positional prior means re-implementing its hooks against *our* detector, not git-merging theirs.
- **`src/ad_reviewer.py` (−184) / `src/ad_validator.py` (−29) / `src/sponsor_service.py` (−110) / `boundaries.py` (−129)** — all rewritten on our side; upstream #320/#362 touch the same files. Treat every upstream backend ad commit as a cherry-pick-and-port, never a clean merge.
- **`frontend/src/components/AdReviewModal.tsx`** — both sides changed it (ours +258/−14). The ad-editor *subcomponents* are identical, but the modal shell needs hand-reconciliation: keep our peer overlay / jump-to-peer / play-while-drag while folding in any upstream modal fixes.
- **`frontend/src/api/sponsors.ts`, `src/api/sponsors.py`, `src/database/sponsors.py`** — diverged on both sides; #325's sponsor-list pattern-stats enrichment must be re-applied onto our sponsors backend, not merged.
- **`frontend/src/pages/Settings.tsx` + `settings/AdReviewerSection.tsx`** — upstream #303 deletes our standalone section and refolds it under Experiments; if we keep our section layout this is a direct structural conflict. Decide layout ownership before pulling #302/#303.
- **`src/seed_data/sponsors_final.csv`** (upstream renamed to `validator_known_sponsors.csv`, #296/#306) — we kept the old name; the rename + 423-line content churn will conflict on the file path itself.
